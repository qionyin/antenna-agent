# V2.2.3 Dynamic Plan And Review Reflection

## Summary

V2.2.3 changes the default mock task flow from the fixed seven-stage packet chain
to a central-agent generated `dynamic_plan`.

The seven packet names remain available as:

```text
reference_template
legacy compatibility path
test comparison path
```

They are no longer the default required path for new tasks.

## 前后对比结论

V2.2.3 不是单纯增加一个前端字段，而是把任务主流程从
“固定七阶段”改成“中枢按目标动态生成计划”。

核心差异：

| 项目 | V2.2.2 之前 | V2.2.3 |
|---|---|---|
| 默认流程 | 固定七阶段 packet chain | 中枢生成 `dynamic_plan` |
| 七阶段地位 | 默认强制主流程 | reference / legacy / test 对照 |
| 中枢能力 | 路由 skill，执行层仍偏固定 | 生成步骤、记录计划版本、决定 reroute |
| 每步 agent | 主要跟 packet executor / challenger 绑定 | 每个 dynamic step 都有 task_agent + review_agent |
| 审查范围 | 主要审 packet / skill 输出是否合格 | 审每一步目标、证据、逻辑、依赖、风险 |
| Reflection | 无统一结构 | 并入 global_review_agent 输出 |
| Reroute | 主要靠人工或固定流程 | 审查触发后最多自动 reroute 1 次 |
| 真实 CST | V2.0 有审批门，但无 dynamic_plan 展示 | real 任务也生成 preflight/approval/cst_run/parse/review/report 计划 |


## Main Changes

### 1. Dynamic Plan Default

New default task creation now writes:

```text
task_metadata.dynamic_plan
task_metadata.dynamic_plan_history
task_metadata.active_dynamic_plan_version
task_metadata.global_review_records
task_metadata.reflection_records
```

The plan is generated by:

```text
central_agent -> dynamic_planner.task_agent
global_review_agent -> dynamic_planner.review_agent
```

Each dynamic step contains:

```text
step_id
step_goal
task_agent
review_agent
inputs
outputs
evidence_refs
required_skills
gate_condition
status
```

### 2. Legacy Seven-Stage Compatibility

The old packet chain still exists through:

```python
Scheduler.create_legacy_packet_chain_task(...)
```

This keeps existing packet artifacts and adapter-gate tests available without
forcing every new task through all seven packets.

### 3. Review Agent Reflection

Reviewer output now includes:

```text
decision
evidence_level
blocking_findings
required_fixes
reflection
reroute_suggestion
```

Reflection is part of the review agent, not a separate agent.

The reviewer can now mark:

```text
false_positive
false_negative
wrong_primary
missing_dependency
unsafe_execution
weak_evidence
none
```

### 4. One-Time Auto Reroute

When review returns:

```text
decision = reroute
reflection.reroute_required = true
```

the central agent may produce one new dynamic plan version.

The limit is:

```text
max_auto_reroutes = 1
```

This prevents infinite reflection loops.

### 5. Real CST Still Approval-Gated

Real CST task creation now also records a dynamic plan with:

```text
preflight
approval
cst_run
parse
review
report
```

The solver step keeps an explicit approval gate:

```text
real_cst approval required
```

V2.2.3 does not run real CST without the existing V2.0 approval path.

## Frontend
