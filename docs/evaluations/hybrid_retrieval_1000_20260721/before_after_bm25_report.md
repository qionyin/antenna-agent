# Hybrid Retrieval F1 阈值与 BM25Okapi 对比

测试集固定为同一批 1000 条：L2 500 条、L3 500 条、正向 800 条、拒绝边界 200 条；
固定种子为 `20260721`。

## 选择规则

阈值选择以宏平均 `F1@K` 为主指标：

```text
F1@K = 2 * Precision@K * Recall@K / (Precision@K + Recall@K)
```

正确校准必须先取得未过滤 TopK，再扫描阈值。最终采用分层最优值：

```text
L2 = 0.05
L3 = 0.03
```

## 核心对比

| 阶段/算法 | Precision@K | Recall@K | F1@K | Hit@K | 负例拒绝率 | 平均耗时 ms |
|---|---:|---:|---:|---:|---:|---:|
| 原始 Redis Hybrid | 35.19% | 55.42% | 43.05% | 86.88% | 3.00% | 22.141 |
| 分数归一化后、阈值前 | 35.92% | 56.48% | 43.91% | 89.00% | 6.50% | 28.971 |
| 最终 Redis Hybrid | 36.12% | 56.31% | **44.01%** | **88.88%** | 11.00% | 24.062 |
| BM25Okapi | 35.93% | **56.67%** | 43.97% | 73.00% | **50.00%** | **0.125** |

## 结论

- 最终 Hybrid 的 `F1@K=44.01%`，是生产候选中的最高值，略高于 BM25 的 `43.97%`。
- 相比原始 Hybrid，Precision 提升 `0.93` 个百分点，F1 提升 `0.96` 个百分点。
- Hybrid 的 Hit@K 比 BM25 高 `15.88` 个百分点，语义和模糊输入覆盖更好。
- BM25 查询速度明显更快，负例拒绝率也更高，适合作为快速候选召回或并行基线。
- `0.05/0.03` 看似较低，但它们对应当前归一化分数分布的 F1 峰值；人为提高阈值会降低综合指标。

## 校准纠错

早期校准曾在已经经过 `0.30` 阈值过滤的结果上再次扫描，属于循环校准，已废弃。
现有 `threshold_calibration.json` 已由未过滤候选重新生成。
